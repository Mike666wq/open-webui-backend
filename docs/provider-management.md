# 供应商与模型管理

在「设置 → 外部连接 → 提供商账户」添加连接。New API 使用「New API / OpenAI-compatible」，填完整 Base URL 与 API Key；硅基流动使用 SiliconFlow。账号登录只展示实际授权能力，不包含额外媒体 API 权限。

供应商详情分为连接设置、模型、调用记录。手机先选择供应商进入详情，返回列表可切换连接。模型支持搜索、能力与启用筛选、人工分类、启停和显式测试。模型选择与启停在模型标签统一管理。

## 四种不同状态

- 保存连接：凭据已加密保存在服务器，不代表上游可达。
- 获取目录：目录请求成功，不代表模型推理成功，也不会运行付费推理。
- 启用模型：允许有权限的用户选择并调用该模型；新发现模型默认关闭，旧模型保留原设置。
- 测试通过：用户明确同意后进行的一次特定能力请求，不代表所有参数均兼容。超时或失败可能已经产生费用，不自动重试。

模型 ID 使用连接 ID 与上游模型 ID，不同供应商的同名模型不会合并。未知能力需要在已支持的协议范围内人工分类，不能通过改模型名获得厂商专属协议。

## 目录与权限

服务端保存目录，15 分钟有效。过期先显示已保存目录并后台刷新；失败保留旧目录并提示分类错误。新版连接通过数据库租约合并刷新，后台刷新会重新检查连接、凭据版本与权限。各用户的目录快照隔离，目录快照不授予调用权限。凭据、地址改变后需要重新获取目录。

旧版服务端 OpenAI 来源也保存用户隔离的目录，降低偶发网络失败导致模型消失的概率。浏览器直连仍是独立高级来源，依赖浏览器所在网络与跨域设置，不计入服务端调用记录。

## 旧连接迁移

管理员点击「预览迁移」，核对地址、模型、原模型 ID、共享说明与冲突归属，再确认单个来源。预览仅请求目录。迁移复制加密凭据，保留原模型访问规则和聊天 ID 引用，并禁用对应旧来源。操作幂等，数据库保存失败不切换原连接。

迁移不会扩大原访问权限。同名冲突必须选择原 ID 的归属，其他来源保留稳定 ID。包含自定义请求头、Azure 或其他未适配协议的来源阻止迁移，先保留旧配置；关闭持久配置时不能迁移。浏览器直连不迁移。

## 辅助模型与调用记录

在管理员「界面」设置选择本地／外部辅助任务模型。未配置或所选模型不可用时，标题、标签、后续建议跳过；查询生成提示配置，搜索和检索明确提示使用原问题、不额外调用查询生成模型；旧版工具选择需要配置辅助模型，不回退到聊天模型。模型仍须通过正常访问权限检查。

标题、标签、后续建议和搜索查询可以分别指定自己的模型。默认模型对全部辅助任务生效；某个用途单独指定后只覆盖该用途，留空表示继续沿用默认模型，因此升级不会让既有配置失效。某个用途在默认与单独指定都为空时，该用途不自动生成，也绝不回退到聊天模型。

调用记录包含请求用途、模型、连接、状态、耗时及上游实际报告的 token，支持本轮查看及最近 30 天汇总。明细最多 500 条，汇总覆盖有效时间内全部记录。没有 usage 时显示未知，不推算费用或 ChatGPT 套餐余额。记录不保存提示词、回答、音频或凭据。用户只能看自己的记录；管理员汇总仅包括自己的记录及共享连接。启用前的请求不能补录。后台每小时清理超过 30 天的记录，查询立即排除过期记录。

## 供应商类型与白名单

供应商按接入协议分类登记，模板目录分四组：官方、国产、网关、其他。当前真正实装的只有 OpenAI 兼容族（OpenAI、MiniMax、DeepSeek、硅基流动、百炼、New API / One API 等网关）与 ChatGPT（OAuth）。Anthropic、Gemini、Azure OpenAI、Bedrock 与本地推理只登记模板、不实装：添加时明确拒绝，不会按 OpenAI 协议误调。

厂商列表只是候选池，不是可用模型清单。厂商返回的模型要先拉取成候选池快照，用户勾选后才进入白名单；只有白名单里的模型会出现在聊天选择器。拉取动作只写快照，不改白名单。快照按用户隔离，不授予调用权限。

厂商级开关取代逐模型关闭：关掉一个供应商会整体下线它的模型，模型自身的启用状态保留，恢复开关后模型原样回来。

白名单行的稳定模型 ID 是 `provider:<连接 ID>:<上游模型 ID>`，不同供应商的同名模型不会合并。白名单模型可设置用途（聊天、语音转写、语音合成、生图）、自定义显示名，以及逐用途的连通性测试结果；用途决定它在聊天里承担什么任务，也决定它出现在哪些选择器里。

白名单数据存在新表里，迁移期间双读兜底：新表有记录走新表，否则沿用旧配置里的 `_model_*` 键；写路径只写新表。迁移失败时保留旧配置与旧模型列，不丢模型。

出站请求按五类归因：连接、厂商网络、鉴权、限流、上游。后端对每一类给出可展示的中文提示，前端按分类显示标题与提示，不再直接把原始异常抛给用户。

## 按服务接入与分用途模型（P-002）

连接创建时可提交 `model_selections`（upstream_id、display_name、uses、source），
后端按模板校验每个用途的适配器归属后与连接同事务入库；它与旧的 `model_ids`
并存但不得互相矛盾，两种写法同时出现且不一致时返回 400，而不是静默取其一。
只启用了转写的媒体连接（如 MiniMax 无远程列表接入）不会把转写模型混进聊天
目录：`GET /providers/models?purpose=` 按用途过滤，聊天选择器只看到带 chat
用途的模型。

模板的每个服务声明带 `operations` 元数据（如 `openai-image` 为
`['edit','generate']`，MiniMax / 硅基流动生图仅 `['generate']`）。前端据此决定
是否展示编辑入口，后端在编辑请求出站前按实际生效适配器再次判定——生图可用
不等于编辑可用。合成音色经 `fetchProviderVoices(连接, 用途, 类型)` 按服务拉取，
不跨服务借用其他厂商的预设音色。

## 验证边界

CI 使用合成凭据与模拟服务，验证目录、启停、权限、刷新、迁移和流式调用，不访问真实付费模型。真实厂商调用由用户在模型详情显式触发。发布顺序为前端和 Android，再固定该前端版本构建后端镜像。
